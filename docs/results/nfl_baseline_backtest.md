## Protocol

- Each target week is projected from data strictly before that week (`dfs.data.nflverse.before`): schedules with closing spread/total, the week's final injury report and weekly roster status (game-day `INA` inactives are NOT used unless stated), the last depth-chart snapshot before game day, and box scores / snap counts / ff_opportunity from earlier weeks only.
- Actual fantasy points: nflverse weekly box scores scored by `dfs.scoring.score` with the repo's `draftkings.nfl` / `fanduel.nfl` tables. Fumbles lost = nflverse `fumbles_lost_total` (adds fumbles lost on kick/punt returns, which both sites charge). DST: sacks = the opponent's official sacks taken, defensive TDs include fumble-recovery TDs, blocked kicks include PATs; points allowed DK = opponent points minus 6 per opponent defensive TD (its XP still counts) and 2 per safety, FD = the site formula 6 x (offensive + own-fumble-recovery TDs) + 2pt + XP + 3 x FG. Checked against the season averages printed in the real 2026 week-6 DK and FD salary files (weeks 1-5): DST 20/20 teams on each site (DK rounds half up); offense, 257 players matched by name and team: FD season totals (FPPG x Played) agree for 256 (the other shows last season's line), DK averages for all 257 once DK's games count is used (10 players have extra special-teams-only games).
- **Pool A** (primary): every QB/RB/WR/TE player-game with >= 25% offensive snap share in the target week, plus every DST. Same rows for every model. The model's point forecast is its mean *conditional on playing* (QB: on starting), comparable with 'average when played' baselines.
- **Pool B**: pool A plus each team's top players (QB1, RB1-2, WR1-3, TE1) by the model's unconditional mean or by season-to-date average, who did not reach the snap threshold or did not play (actual = their real points, often 0; injured regulars therefore enter). The model is scored on its *unconditional* mean (availability included); baselines are unchanged.
- Baselines (point-in-time): `season_avg` = season-to-date average points per game played; `last3` = last 3 games played; `xfp_avg` = season-to-date average of ff_opportunity expected fantasy points (PPR; minus 0.5 x expected receptions for FD). Players with no game this season fall back to last season, then to the position median.
- Metrics: MAE, RMSE, bias = mean(pred - actual), spearman = mean within-week rank correlation, top3 = share of each week's actual top-3 at the position that were in the projected top-3, cover80 = share of actuals inside [p10, p90] (target 0.80), pinball = mean quantile loss over p10/p50/p90.
- Hyper-parameters were tuned on 2024-2025 weeks 3-17 only (DK, pool A, mean of per-position MAE, then pinball loss for dispersion). No parameter was chosen from 2026 results. Disclosure: 2026 weeks 3-6 were also run during development with the untuned defaults and one interim parameter set (as a smoke test), and 2026 QB-starter hit rates were visible when the depth-chart-first starter rule was adopted on 2025 evidence (95.4% vs 92.9% on 2025 games).

## Changes after review

Figures in this list describe the pre-fix code and were measured during the review; they are not recomputed by this report.

- Fumbles lost now use nflverse `fumbles_lost_total`, which includes fumbles lost on kick/punt returns; before, returners' DK/FD season averages were off by 1 (DK) / 2 (FD) points per return fumble.
- QB start probabilities: the start chain used P(logs an offensive snap), which for a backup is ~0.15-0.4 even when he is the only healthy QB, so when the starter was out the team's start probabilities summed to ~0.3-0.6 (6% of 2024-25 team-weeks below 0.9). It now uses P(dressed: game-day ACT) and is conditioned on exactly one QB starting.
- Availability adds the pre-game depth-chart bucket (starter / backup / other): healthy depth-chart starters without recent snaps (season openers after a late-season injury, returns from IR) were scored as deep backups (P(plays) ~0.5 against an observed ~0.9).
- Naive baselines: the documented position-median fallback never applied (the position came from the same empty history), so players without a game in two seasons got 0 (e.g. two starting QBs in 2026 weeks 3-4); they now get the position median.
- The week context keeps only pre-game schedule columns (target-week box-score columns were carried in `WeekContext.games`, unused but one step from a leak); duplicate injury rows keep the latest report.

## Notes and known weaknesses

- No player props or opponent-specific player adjustments: the market enters only through team spread/total; props would be the strongest single extra input.
- Usage is share-based without routes or alignment data; role changes inside a week (new starter announced, trade) reach the model only via the depth chart snapshot and the injury report.
- QB starter identification picks the actual starter ~93-95% of the time from depth chart + last start + availability; a wrong pick moves the QB and his receivers. The LLM research stage must confirm starters.
- Pool A conditions on >= 25% snaps, which biases every model's error low for players who barely played and makes low projections look under-projected (selection effect on the snap threshold).
- Week 17-18 rest decisions, weather, and in-game injury risk beyond a flat per-position early-exit rate are not modelled.
- DST points allowed conventions were inferred from 2026 site averages (20/20 teams reproduced on DK and FD); DK's rule (opponent points minus 6 per opponent defensive TD, the XP still counts) differs from the research note and should be re-checked as more games accumulate.
- Stat-line simulation draws players independently; cross-player correlation is left to dfs.sim.
- Quantiles in pool A: fewer actuals fall below p10 than the 10% target (lower tail too long) and more exceed p90. Part of this is selection (pool A excludes the early-exit and low-snap games the played distribution includes); the pinball-tuned dispersion was chosen on 2024-2025 with that same pool.
- Backup QBs are projected as if they start (p_zero = 1 - start probability); relief appearances are not modelled, so their played distribution is too high when they only enter late.
- When a backup QB starts, team passing volume and efficiency still come from the team's history with its usual starter; receivers and the opposing DST are not adjusted for the QB change.
- The below-p10 rate understates lower-tail coverage for low-usage players whose played distribution has an atom at 0 (p10 = 0, so an actual 0 is not 'below' it); cover80 counts those as covered.
